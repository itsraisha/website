Questions

Interview-style cybersecurity answers, written like a study vlog.

A growing Q&A section for questions I want to be able to answer clearly in SOC, blue-team and junior security interviews.

SOC fundamentals

How would you investigate repeated failed SSH logins followed by one successful login?

I would treat the successful login differently because it changes the story from attempted access to possible compromise. I’d check the source IP, timing, username, number of failures, authentication method and whether the success came after a brute force pattern. Then I’d pivot to host activity: new files, permission changes, unusual commands, persistence attempts and deletion activity.

Detection

Why is multi-source correlation stronger than one alert by itself?

A Suricata alert can show scanning, but not what happened after login. Authentication logs can show access attempts, but not what the user did. Auditd can show file activity, but not how the attacker arrived. Correlating all three gives a fuller timeline and reduces guesswork.

Threat analysis

What did the honeypot lab teach you about attribution?

Source country is not the same as attacker identity. A lot of malicious traffic can come from cloud infrastructure, VPNs or compromised systems. I would describe geographic patterns cautiously and focus more on behaviour, ports, reputation, payloads and repeatable indicators.

Application security

What is IDOR and how did you fix it in the hospital app?

IDOR happens when the application trusts an object ID from the user without checking ownership. In the appointment cancellation flow, changing the ID in the URL could affect another patient’s appointment. The fix was to enforce server-side ownership checks using the logged-in session before allowing the action.

Security operations

What makes an alert noisy?

An alert becomes noisy when it fires too broadly, lacks context, or catches normal system behaviour without enough filtering. In my Auditd work, broad deletion rules also captured Wazuh’s own process activity. The lesson was to tune scope carefully instead of assuming every technically correct alert is useful.

Malware behaviour

Why does WannaCry still matter if the original outbreak was years ago?

Because older vulnerabilities continue to matter when systems remain unpatched or exposed. My honeypot still captured WannaCry-like samples targeting SMB, which shows attackers keep scanning for old weaknesses at internet scale. Legacy risk does not disappear just because the headline moved on.
